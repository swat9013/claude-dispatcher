# ADR 0030: 結果の分からない引き継ぎを残して止まるときの error の行は、引き継ぎが remote に届いていないときも同じに書く

- Status: Accepted
- Date: 2026-10-26
- ADR 0027 の決定を補う (置き換えない)。ADR 0027 は orphan のための着手宣言の引き継ぎを決めたが、引き継ぎの push の結果が分からないまま止まるときに書く行の水準は決めていなかった

## Context

同じマシンで起動し直した loop は、生きている orphan の作業対象に残った死んだ loop の着手宣言を、旧 sha を期待値にした置き換えで自分の名前に引き継ぐ (ADR 0027)。置き換えの push が結果の分からない失敗 (remote に届いたかを決められない失敗) をすると、loop はその作業対象を覚えておき、次の tick で ref と着手宣言の commit message を読んで、届いていたかを決める (formats.md §12 の 8)。

届いたかを決める前に loop が止まると、loop は覚えておいた作業対象ごとに `error` の行 (`orphan のために引き継いだかもしれない着手宣言を残して止まる (…)`) を書く。括弧の中は、orphan がまだ生きているか、終わっていたかで分かれる。

この行は、引き継ぎの push が実は remote に届いておらず、remote に残っているのが死んだ持ち主の元の着手宣言で、その commit message を読めないまま止まるときにも出る。このとき自分の名前の着手宣言は remote に無い。今の実装は、結果の分からない引き継ぎを覚えるとき、push の期待値にした旧 sha を覚えておかない。このため、着手宣言の commit message を読めない限り、届いたかを見分けられない。

## Decision

**届いたかを決める前に止まるときは、引き継ぎが remote に届いていたかによらず、同じ文言の `error` の行を同じ水準で書く。** 文言の「かもしれない」が、届いたかが分からないことを表す。着手宣言と生存報告の扱いも変えない。

- 届いていない側で出る行の被害は、`error` の水準の行が 1 本余計に出ることだけで、着手宣言と生存報告の扱いは変わらない
- 届いていた側では、自分の名前の着手宣言が remote に残り、orphan の claude と重なりうる。この行は、止まった後にも残りうるその着手宣言を、止まる時点で知らせる行なので落とせない
- 偽の `error` の行が 1 本出る費用より、本物を見落とす費用のほうが重い

## Consequences

### 良い影響

- 届いていた側 (自分の名前の着手宣言が残りうる側) を、運用者が `error` の行から見落とさない

### 悪い影響 / 制約

- `error` の行を監視する運用では、自分の名前の着手宣言が remote に無いときにも気づかされる

## Alternatives considered

### 届いていないと分かるときだけ水準を下げるか、行を書かない

- 却下理由: 今の実装では、commit message を読めない限り届いたかを見分けられない。見分けられないまま水準を下げるか行を落とすと、届いていた側の気づきまで落ちる

### 行を `warn` などの低い水準へ変える

- 却下理由: 届いた側と届いていない側を見分けられないので、届いていた側の行の水準も一緒に下がる

### 旧 sha を覚えて ref の sha と比べる

- 引き継ぎの push の期待値にした旧 sha を覚えておき、次の tick で ref の sha が旧 sha のままなら、commit message を読めなくても「届いていない」と決める案
- この ADR では採らず、別 issue (#477) で扱う: 行の水準ではなく、結果の分からない引き継ぎの決着の仕方を変える案で、コードと test の変更が要る。決着できるのも、ref の sha が旧 sha のままのときだけで、ref が別の sha なら今と同じく commit message が要る。このため、偽の行は減るが無くならず、この ADR の決定 (行の文言と水準を変えない) は採っても変わらない
