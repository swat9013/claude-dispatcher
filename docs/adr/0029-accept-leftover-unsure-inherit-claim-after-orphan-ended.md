# ADR 0029: 結果の分からない引き継ぎを決着させないまま orphan が終わって止まるとき、着手宣言が残ることを受け入れる

- Status: Accepted
- Date: 2026-10-26
- ADR 0027 の決定を補う (置き換えない)。ADR 0027 は、引き継いだ loop が止まるとき orphan が生きていれば着手宣言と生存報告を残すと決めたが、引き継ぎの push の結果が分からないまま止まる経路は決めていなかった

## Context

ADR 0027 では、同じマシンで起動し直した loop が、生きている orphan の作業対象に残った死んだ loop の着手宣言を、旧 sha を期待値にした置き換えで自分の名前に引き継ぐ。置き換えの push が結果の分からない失敗 (remote に届いたかを決められない失敗) をすると、loop はその作業対象を覚えておき、次の tick で ref と着手宣言の commit message を読んで、届いていたかを決める (formats.md §12 の 8)。

届いたかを決める前に loop が止まると、loop は着手宣言が remote にあるかも、あればその sha も知らないので、着手宣言を消せない。止まる時点で orphan が生きていれば、引き継いだ着手宣言と同じく、着手宣言も生存報告も残して止まる (ADR 0027)。orphan が終わっていれば、生存報告を消し、着手宣言には触らずに止まる。

後者で着手宣言が remote に届いていると、自分の名前で生存報告の無い着手宣言が remote に残る。他の loop は、持ち主の生存報告が無い着手宣言として、持ち主を死んだとみなすまで (formats.md §12 の 5) その作業対象を起動しない。

今の tick の順では、着手宣言の commit message を読める限りこの経路に届かない (理由は formats.md §12 の 8)。commit message を読めないまま orphan が終わり、その後に loop が止まると届く。

## Decision

**結果の分からない引き継ぎを覚えたまま、orphan が終わった後に loop が止まるときは、生存報告を消し、自分の名前の着手宣言が生存報告の無いまま remote に残りうることを受け入れる。**

- orphan は終わっているので、着手宣言を残して守る相手の claude がいない
- 残った着手宣言は、他の loop が持ち主を死んだとみなす (formats.md §12 の 5) まで、その作業対象の起動を遅らせるだけで、二重実行にはならない

## Consequences

### 良い影響

- 生存報告を orphan が作業を続けうる間だけ残す規則 (ADR 0027。コードでは `internal/coord/board.go` の `Board.Leave`) に、例外を作らずに済む

### 悪い影響 / 制約

- 着手宣言が remote に届いていたとき、他の loop は持ち主を死んだとみなすまで、その作業対象を起動しない
- この経路に届くのが commit message を読めないときだけなのは、tick の手順の順 (覚えた引き継ぎの突き合わせと orphan の確かめの前後。formats.md §6) に頼っている。順を変えるときは見直す (formats.md §12 の 8)

## Alternatives considered

### 結果の分からない引き継ぎが決着していない間は、orphan が終わっていても生存報告を残す

- 却下理由: 生存報告は、持ち主の作業が続いていることの表明。ADR 0027 は orphan が生きていれば生存報告を残すと決め、`Board.Leave` も生存報告を orphan が作業を続けうる間だけ残す。orphan が終わっているのに残すと、作業の無い持ち主が生きているという事実と違う表明を、loop が止まった後も出し続けることになる
