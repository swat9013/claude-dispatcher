# ADR 0027: 生きている orphan の作業対象の着手宣言を、同じマシンで起動し直した loop が引き継ぐ

- Status: Accepted
- Date: 2026-10-23
- ADR 0011 の「まれな二重実行は受け入れる」に、orphan の経路を足す

## Context

ADR 0011 は、死んだ loop の着手宣言を旧 sha を期待値にした置き換えで乗っ取る形にし、network が切れた loop が生きたまま死んだとみなされたときの、まれな二重実行を受け入れた。

落ちた loop が残した orphan の claude は、loop が死んだ後も作業対象の作業を続ける。同じマシンで起動し直した loop は、worker log の flock で orphan を観測し、その作業対象を起動せず、死んだ loop の着手宣言も消さない (#382)。別のマシンの loop は orphan を観測できないので、生存報告の間隔の 3 倍の後に着手宣言を乗っ取って worker を起動する。loop が落ちるたびに起こりうるので、ADR 0011 の「まれ」に入らない。

## Decision

**同じマシンで起動し直した loop は、生きている orphan の作業対象に残った死んだ loop の着手宣言を、旧 sha を期待値にした置き換えで自分の名前に引き継ぎ、自分の生存報告で守る。orphan が終わったら、引き継いだ着手宣言を消す。**

- 持ち主が同じマシンの別の loop 名 (loop 名の hostname の部分が同じ) なら、生存報告の間隔の 3 倍を待たずに死んだとみなして引き継ぐ。同じ scope の loop は 1 台に 1 つしか立たない (scope key の lock) ので、それは落ちた前の loop で、待つと、前の loop が生きている間から sha を見ていた別のマシンの loop に先に乗っ取られる
- 引き継いだ着手宣言は claim を立てない。別のマシンの loop は、生きている loop の着手宣言として扱い、乗っ取らない
- 引き継いだ loop が止まるとき、orphan がまだ生きていれば、着手宣言と生存報告を消さずに残す (止められない claude を残して止まるときと同じ。次に同じマシンで起動した loop がまた引き継ぐ)
- 同じマシンで loop を起動し直さない間は、別のマシンの loop が乗っ取りうる。この経路の二重実行は受け入れる

## Consequences

### 良い影響

- loop が落ちても、同じマシンで loop を起動し直せば、orphan の作業対象に別のマシンが worker を重ねない

### 悪い影響 / 制約

- 落ちたマシンで loop を起動し直さないと、orphan の作業対象は ADR 0011 のとおり別のマシンに乗っ取られ、二重実行になる
- 同じマシンかは loop 名の hostname で見るので、hostname が変わったマシン (名前の衝突で変わる macOS など) では待たずに引き継げず、別のマシンに先に乗っ取られうる。同じマシンでも state dir の違う loop (OS の user や `XDG_STATE_HOME` が違う) は 1 台に 1 つの前提に入らず、生きている loop の着手宣言を引き継ぎうる
- 同じ hostname のマシンが 2 台あると、別のマシンの生きている loop の着手宣言を、その作業対象に orphan がいるときに引き継ぎうる
- 自分の loop 名の着手宣言で claim の無いもの (消し損ねた着手宣言) を消す規則に、引き継いだ着手宣言という例外が増える

## Alternatives considered

### この経路の二重実行をすべて受け入れ、記録するだけにする

- 却下理由: loop が落ちるたびに起こりうるので、ADR 0011 の「まれ」に入らない
